# AI Config

This is a dotfiles repo for AI agents — the Linux-dotfiles idea (one repo, your whole
config, clone it anywhere), applied cross-platform and cross-agent instead of just
cross-shell. Everything lives under `.ai/`: project instructions and skills (portable,
travels with any repo you're working in), this machine's Claude Code setup, and the CLI
that applies either of those to wherever they need to land.

## Design principle

One source of truth in `.ai/`. Almost everything else at repo root is *generated* —
written by the CLI, never hand-edited. The two exceptions are hand-authored, tool-specific
files that need metadata (model, tool list) `.ai/` doesn't model; those live in
`.ai/wrappers/<tool>/` and get copied out verbatim, still never hand-edited at their final
path.

## Structure

```
.ai/
├── instructions.md, skills/, workflows/, agents/    ← project config: global rules, skills
│                                                        (core + per-project), workflows,
│                                                        tool-agnostic agent behavior
├── mcp-servers.json           ← MCP server definitions (generic schema)
├── wrappers/<tool>/<path>     ← hand-authored, tool-specific files (model/tools metadata
│   ├── claude/agents/, claude/commands/               .ai/ can't model) — copied verbatim,
│   └── github/agents/, github/skills/, github/prompts/ never templated
├── dotfiles/
│   ├── claude/{skills/, plugins/, settings.json, statusline-combined.ps1}
│   │                            ← this machine's ~/.claude — skills you wrote, the plugins
│   │                              you have installed, settings.json, hooks
│   └── wiki/                   ← reading material — release tracker, curated links, the
│                                  mental model behind them. Nothing here is auto-loaded by
│                                  any tool, it's just for you.
└── cli/
    ├── index.js                ← router: `wrap` (default) | `dotfiles`
    ├── wrap.js                 ← generates project config below from .ai/
    ├── dotfiles.js             ← applies .ai/dotfiles/claude/ to ~/.claude (import-only)
    └── lib.js                  ← shared write/mirror helpers

# Generated by `ai-config wrap`, gitignored — edit .ai/, not these
CLAUDE.md, AGENTS.md, GEMINI.md
.cursor/rules/project.mdc, .windsurfrules
.mcp.json, .vscode/mcp.json
.github/copilot-instructions.md
.claude/agents/, .claude/commands/, .github/agents/, .github/skills/, .github/prompts/
                                ← copied verbatim from .ai/wrappers/, not templated, but
                                  still: edit the .ai/wrappers/ copy, then re-run the CLI

package.json                   ← bin: ai-config → .ai/cli/index.js (npm needs this at root)
```

Every file at repo root sits at a path some tool auto-detects by fixed convention — that's
hardcoded in each tool, not configurable, no way around it (a symlink would "work" on
Linux/macOS and silently turn into a text file containing the link's target path on
Windows without dev mode + `core.symlinks=true`, breaking every tool reading it — not
worth the risk). Nothing about `.ai/` itself is fixed by any convention, so it's the only
thing actually tracked by git: **everything in the file list above except `.ai/`,
`package.json`, `README.md`, and `.gitignore` is gitignored** — real files on disk once
you've run the CLI, never committed. `git ls-files` on this repo shows almost nothing but
`.ai/`.

**First thing after cloning:** `node .ai/cli/index.js --all` — until you do, there's no
`CLAUDE.md`, so Claude Code (or any other tool) has nothing to read yet.

## Generating the project config

```sh
node .ai/cli/index.js                       # interactive menu, pick agents by number
node .ai/cli/index.js --claude --copilot    # skip the menu
node .ai/cli/index.js --all
```

No arrow-key TUI dependency — a plain numbered menu via Node's built-in `readline`, correct
on every terminal at zero extra installs. Reads `.ai/instructions.md`, `.ai/skills/`,
`.ai/workflows/`, `.ai/agents/`, `.ai/mcp-servers.json`, `.ai/wrappers/`; doesn't know
Joomla or Astro, it's generic delivery for whatever's actually in those folders.

- `--target <dir>` — where to write (default: cwd)
- `--source <dir>` — where to read `.ai/` from (default: `<target>/.ai`)
- If `<source>` doesn't exist yet, it's scaffolded empty so there's somewhere to start writing.

To use this on another project: `cd` there and point `--source` at this repo's `.ai/`:

```sh
cd /path/to/other-project
npx github:David7ce/ai-config --source /path/to/ai-config/.ai
```

Editing workflow, either repo:

1. Edit rules in `.ai/instructions.md`, `.ai/skills/`, `.ai/workflows/`, `.ai/agents/` — re-run the CLI, every tool picks it up.
2. Tool-specific metadata (Claude subagent model, Copilot tool list, argument hints): edit the file under `.ai/wrappers/<tool>/`, re-run the CLI. Never hand-edit `.claude/agents/...` etc. directly — it gets overwritten.
3. MCP servers: edit `.ai/mcp-servers.json` by hand (use `{ "fromEnv": "VAR_NAME" }` for secrets — never inline a token), then `node .ai/cli/index.js --mcp`.

## Applying this machine's dotfiles

```sh
node .ai/cli/index.js dotfiles list      # drift: .ai/dotfiles/claude vs ~/.claude, read-only
node .ai/cli/index.js dotfiles import    # applies it — mirror, deletes extras in ~/.claude
node .ai/cli/index.js dotfiles remove <skill-name>
```

One direction only, by design: `.ai/dotfiles/claude/` is what you hand-edit (skill files,
`settings.json`, the plugin registry) — with help, via prompts, rather than through an
automated capture-from-live step. There's no `export`; nothing in `~/.claude` is ever the
source of truth.

## Installing community skills with skills.sh

[skills.sh](https://skills.sh) (by Vercel) is an open registry of reusable agent skill
files. It auto-detects your tech stack and installs matching skill documents directly
into your project.

```sh
npx skills                    # scan repo, offer a curated list
npx skills add nextjs         # or install a specific skill by name
```

Drop the output into `.ai/skills/projects/<name>/` to keep it within this repo's
single-source-of-truth layout — they're plain markdown, no lock-in, but review before
committing.
